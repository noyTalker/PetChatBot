# 🐾 PetChatBot — מערכת Triage וטרינרית מבוססת AI

מערכת תומכת החלטה לטריאז' וטרינרי, המשלבת צ'אטבוט אינטראקטיבי עם מודל למידת מכונה (XGBoost), לצורך הערכה ראשונית של רמת הדחיפות של מצבים רפואיים בכלבים ובחתולים.

> ⚠️ **המערכת אינה מהווה אבחון רפואי ואינה מחליפה שיקול דעת מקצועי של וטרינר.** מטרתה לספק כלי עזר ראשוני בלבד, ולסייע לבעלי חיות מחמד להבין האם קיימת הצדקה לפנייה דחופה לטיפול וטרינרי.

🔗 **המערכת באוויר:** [noytalker.github.io/PetChatBot](https://noytalker.github.io/PetChatBot/)

## 📖 על הפרויקט

בעלי חיות מחמד נדרשים לעיתים להעריך במהירות האם מצבו של בעל החיים מחייב פנייה מיידית לווטרינר, או שניתן להמתין — ללא כל ידע רפואי מוקדם. **PetChatBot** נועד לגשר על הפער הזה.

הפרויקט משלב שלושה רבדים:

1. **תהליך יצירת תוויות** למאגר נתונים וטרינרי (~10,000 רשומות) שלא כלל מלכתחילה משתנה יעד לדחיפות — באמצעות Sentence Embeddings, קיבוץ ב-K-Means, ואימות מקצועי של וטרינרית.
2. **מודל סיווג (XGBoost)** שנבחר מתוך השוואת 10 מודלים שונים, ומשיג Recall של 0.94 ו-AUC של 0.948.
3. **מערכת תוכנה מלאה** בארכיטקטורת Client-Server, הכוללת צ'אטבוט אינטראקטיבי, שכבת חוקי בטיחות (Red Flags), והפעלת המודל בזמן אמת.

הפרויקט מהווה המשך למחקר אקדמי מלא (ר' דוח הפרויקט המצורף), ומדגים תהליך פיתוח מקצה לקצה — מנתונים גולמיים ועד אב-טיפוס עובד.

## 🏗️ ארכיטקטורה

המערכת בנויה בארכיטקטורת **Client–Server**:

```
┌─────────────────┐      HTTP/JSON      ┌──────────────────┐      Pipeline      ┌──────────────┐
│    Frontend      │  ─────────────────▶  │     Backend       │  ─────────────▶  │  מודל חיזוי   │
│  React + Vite    │  ◀─────────────────  │     FastAPI       │  ◀─────────────  │   XGBoost     │
└─────────────────┘                       └──────────────────┘                    └──────────────┘
        │                                          │
   ניהול השיחה                         Red Flags + Feature Engineering
   הצגת שאלות                          ניהול Session + הפעלת המודל
```

- **Frontend** — ממשק משתמש מבוסס React ו-Vite, מנהל את זרימת השיחה עם המשתמש ומציג את תוצאת ההערכה.
- **Backend** — שרת FastAPI האחראי על ניהול מצב השיחה (Session), מיפוי תשובות המשתמש לפורמט אחיד, והפעלת מודל החיזוי.
- **מודל החיזוי** — קובץ Pipeline מאומן (`vet_triage_xgb_pipeline.pkl`) הכולל את שלבי עיבוד הנתונים ואת מודל ה-XGBoost, נטען פעם אחת בעליית השרת.

## 🔄 איך זה עובד

1. המשתמש בוחר את סוג בעל החיים, מזין פרטים בסיסיים (גזע, גיל, משקל).
2. נבחרת התלונה המרכזית, והמערכת מפנה למסלול שאלות ייעודי (נשימה, הקאות/שלשולים, נוירולוגי וכו').
3. **שכבת Red Flags** בודקת סימנים קליניים קריטיים (קריסה, פרכוסים, דימום חמור וכו') — אם זוהה סימן כזה, המערכת מסווגת מיידית **כחירום**, ללא הפעלת המודל.
4. אם לא זוהה סימן חירום, המידע עובר עיבוד (מיפוי סימפטומים, בניית שדה טקסט מאוחד) ומועבר למודל **XGBoost**.
5. המערכת מציגה למשתמש את התוצאה: **חירום** או **לא חירום**, יחד עם המלצה מתאימה.

> תרשים זרימת ההחלטה המלא מופיע בדוח הפרויקט, סעיף 4.5.

## 💻 התקנה והרצה מקומית

### דרישות מקדימות
- Node.js (לצורך ה-Frontend)
- Python 3.10+ (לצורך ה-Backend)

### הרצת ה-Frontend
```bash
cd frontend
npm install
npm run dev
```

### הרצת ה-Backend
```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload
```

> 📌 יש לוודא שכתובת ה-API בקובצי ה-Frontend מפנה לכתובת השרת המקומי (`localhost`) בעת פיתוח, ולכתובת השרת המרוחק בעת פריסה.

## 📊 ביצועי המודל

מודל XGBoost נבחר מתוך השוואת 10 מודלי סיווג שונים, תוך דגש על צמצום מקרי **False Negative** (מקרי חירום שלא זוהו):

| מדד | ערך |
|---|---|
| Recall | 0.94 |
| AUC | 0.948 |
| Precision | 0.841 |
| F1-Score | 0.888 |
| False Negatives (מתוך 971 מקרי חירום בבדיקה) | 58 |

פירוט מלא של תהליך ההשוואה, ניתוח SHAP, ובדיקות היציבות (Cross Validation) מופיע בדוח הפרויקט, פרק 6.

## ⚠️ מגבלות ושימוש אחראי

- המערכת היא **אב-טיפוס (Prototype)** למטרות מחקר ולימוד, ולא נבדקה בסביבה קלינית אמיתית.
- הסיווג הוא **בינארי בלבד** (חירום / לא חירום), ללא רמות ביניים.
- תהליך התיוג התבסס על קיבוץ ברמת אשכול ואימות של וטרינרית יחידה, ולא על תיוג קליני פרטני של כל רשומה.
- **המערכת אינה מהווה תחליף לייעוץ וטרינרי מקצועי.** בכל מקרה של חשש לגבי מצבו של בעל החיים, יש לפנות לווטרינר.

פירוט מלא של מגבלות המחקר והמערכת מופיע בדוח הפרויקט, סעיף 7.4.
